# 智能电商客服系统 — 任务书

## 项目目标

基于 **Coze 平台**，搭建一套覆盖售前、售中、售后三大场景的智能电商客服系统，通过工作流编排实现自动化客户服务。

---

## 一、基础准备工作

1. **知识库建设**：创建两个知识库——FAQ 知识库（常见问题解答）和物流政策知识库（各地区配送规则）。
2. **数据库建设**：在 Coze 平台创建三张数据表：
   - `order_tracking_table`：存储订单及物流信息
   - `product_info`：存储商品名称与详情
   - `refound`：存储退换货申请记录
3. **变量配置**：定义若干应用变量（如订单信息、物流信息、退款说明等）和用户变量（闲聊内容），用于工作流间的数据传递。

---

## 二、主对话流（入口与调度中心）

**功能描述：** 作为整个系统的统一入口，负责接收用户消息、管理会话、分发业务请求。

需实现以下能力：

1. **会话管理**：判断是否为新会话，若是则创建会话并记录对话历史；否则续接历史上下文。
2. **输入安全过滤**：对用户消息做关键词过滤与垃圾信息检测，屏蔽违规内容。
3. **FAQ 快速响应**：用户消息优先命中 FAQ 知识库，若有高匹配结果则跳过深度处理，直接回复。
4. **意图识别与路由**：对用户消息进行一级分类，识别为"售前/售中/售后"并调用对应子工作流；无法识别则进入闲聊处理。
5. **最终回复生成**：汇聚各子工作流输出结果，由大模型生成统一、自然的客服回复内容。

---

## 三、售前工作流

**功能描述：** 处理用户购买前的咨询请求。

需实现以下能力：

1. **售前意图细分**：将用户问题进一步识别为商品信息查询、优惠活动查询、物流政策查询或其他。
2. **商品信息查询**：从用户输入中提取商品名称，查询数据库返回商品详情。
3. **优惠活动查询**：调用外部 API（DeepSeek）模拟生成活动方案，解析并返回活动信息。
4. **物流政策查询**：
   - 从用户输入中提取省市地址；
   - 若地址不完整，通过多轮问答引导用户补全（最多循环 10 次）；
   - 校验地址格式后，检索物流政策知识库并返回对应政策。

---

## 四、售中工作流

**功能描述：** 处理交易进行中的用户请求。

需实现以下能力：

1. **订单号提取与验证**：从用户输入中识别合法订单号（TB/JD/PDD 前缀），若无合法格式则循环引导用户重新输入。
2. **售中意图细分**：将用户诉求识别为订单查询、订单修改、物流状态查询或其他。
3. **订单批量查询**：支持同时查询多个订单，区分查询成功与失败的订单，分别提示用户。
4. **订单修改**：
   - 若有多个订单，先让用户选择一个；
   - 校验订单状态（仅"待支付"状态可修改）；
   - 支持修改收件人、手机号、收货地址三个字段，修改完成后更新数据库。
5. **物流状态批量查询**：支持同时查询多个订单的物流信息，区分成功与失败结果，分别回复用户。

---

## 五、售后工作流

**功能描述：** 处理用户购买后的服务需求。

需实现以下能力：

1. **编号获取与验证**：循环引导用户输入订单号或物流号（支持两种路径），直到获取合法编号为止。
2. **售后资格判断**：根据下单时间和订单状态，由大模型判断用户是否具备：
   - **退换货资格**：下单 ≤ 7 天且未签收
   - **维修服务资格**：下单 > 7 天且已签收
3. **退换货处理**：引导用户从预设选项中选择退货理由，将退换货申请记录入数据库，并模拟生成回寄物流信息更新订单状态。
4. **退款处理**：调用 DeepSeek API 模拟退款接口，解析返回结果并向用户同步退款状态。
5. **维修服务处理**：校验维修资格后，更新订单维修记录及物流状态。
6. **无资格提示**：不满足退换货或维修条件时，明确告知用户原因。

---

## 整体架构

```
用户消息 → 主对话流（入口）
              ├── FAQ 知识库命中 → 直接回复
              ├── 意图识别 → 售前工作流 → 商品查询 / 优惠活动 / 物流政策
              ├── 意图识别 → 售中工作流 → 订单查询 / 订单修改 / 物流查询
              ├── 意图识别 → 售后工作流 → 退换货 / 退款 / 维修
              └── 无法识别 → 闲聊处理
```

**一个主对话流 + 三个业务子工作流**，通过意图识别串联，形成完整的智能客服闭环。
