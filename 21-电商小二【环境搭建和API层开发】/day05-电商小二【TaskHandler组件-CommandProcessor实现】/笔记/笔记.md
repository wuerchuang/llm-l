### 1、TaskHandler任务流程分析

* **TaskHandler：作为任务流程处理入口，获取意图识别结果，根据意图识别结果更新对应任务状态数据，根据当前活跃任务步骤向下推进**

* **TaskHandler传入参数有三个**

-- 第一个 意图识别结果 list[command]

```
  "task": {
    "commands": [
      {"command": "start_flow", "flow": "<flow_id>"},
      {"command": "set_slots", "slots": {"<slot_name>": "<value>"}},
      {"command": "resume_task", "task_id": "<task_id>"},
      {"command": "cancel_task", "task_id": "<task_id>"}
    ]
  },
```

-- 第二个 state

-- 第三个 user_message

* **TaskHandler返回结果 list[BotMessage]**



* **TaskHandler具体实现流程**

1. 执行 Commands，修改任务状态。 -- **CommandProcessor**
2. 根据任务状态变化生成提示消息（可选，用户体验友好）。

  --  **TaskLifecycleResponder**

3.从活动任务的当前 Step 开始推进 Flow。 --**FlowExecutor**

4.合并前两个阶段产生的消息。



* **为了结构更加清晰，把上面步骤分为三个组件实现**

**CommandProcessor**： 根据意图识别结果 Commands，修改state数据

**TaskLifecycleResponder**：根据任务状态变化生成不同中文提示

**FlowExecutor**：推进流程步骤实现



### 2、CommandProcessor

```python
"""
这个模块 TaskHandler里面commandProcessor模块，
作用：根据意图识别结果更新state状态数据
"""
from langchain_protocol import TasksEvent

from atguigu.domain.state import DialogueState, TaskInstance
from atguigu.plan.command import Command, StartFlowCommand, ResumeTaskCommand, SetSlotsCommand, CancelTaskCommand
from atguigu.task.flow.models import FlowCatalog, Flow
from atguigu.task.tasklifecycle.models import TaskEvent


class CommandProcessor:
    # commands: 意图识别结果列表
    async def run(self,commands:list[Command],
                  state:DialogueState,
                  flow_catalog:FlowCatalog)->list[TaskEvent]:
        events:list[TaskEvent] = []
        # 遍历commands
        for command in commands:
            event:TaskEvent = self._execute_command(command,state,flow_catalog)
            if event:
                events.append(event)
        return events

    # 处理command
    def _execute_command(self,
                         command:Command,
                         state:DialogueState,
                         flow_catalog:FlowCatalog)->TaskEvent:
        # 根据不同类型command做不同处理
        # {"command": "start_flow", "flow": "<flow_id>"},
        if isinstance(command,StartFlowCommand):
            # 获取流程id
            flow_id = command.flow
            # 根据流程id获取流程对象
            flow:Flow = flow_catalog.get_flow_by_id(flow_id)

            # 根据流程id 获取流程里面 开始类型步骤id
            start_step = flow.get_start_step()

            # TaskInstance对象
            task = TaskInstance(
                flow_id=flow_id,
                step_id=start_step.id,
            )

            # 把创建task任务更新到state里面active里面
            event:TaskEvent = state.tasks.start_task(task)
            return event

        # 槽位数据
        # {"command": "set_slots", "slots": {"<slot_name>": "<value>"}},
        # 设置槽位数据，不需要中文提示
        if isinstance(command,SetSlotsCommand):
            # 更新state里面active槽位
            state.tasks.active.slots.update(command.slots)
            return None

        # 恢复任务
        # {"command": "resume_task", "task_id": "<task_id>"},
        # 恢复前提条件：在中断列表有任务
        if isinstance(command,ResumeTaskCommand):
            event:TaskEvent = state.tasks.resume_task(command.task_id)
            return event

        # 取消任务
        # {"command": "cancel_task", "task_id": "<task_id>"}
        if isinstance(command,CancelTaskCommand):
            event: TaskEvent = state.tasks.cancel_task(command.task_id)
            return event

        raise TypeError(f"Unknown command type")
```

### 4、FlowExecutor（重要）

* **这个组件作用：根据当前active里面步骤id进行流程步骤推进**

* **流程：**

1 当前必须有活跃任务

2 获取当前步骤，根据步骤类型做不同处理，因为五种类型

* **start类型：代表流程开始标识，推进到下一步**
* **collect类型：是否收集槽位数据**

-- 到active找槽位数据，如果active找不到，到对象类型消息获取

-- 如果两个地方都找不到，返回提示给用户

-- 如果可以找到槽位数据，推进到下一步

* **action类型：调用具体业务方法，远程调用中台系统接口**

-- action调用之后，调用之后得到数据放到slots里面，为了后面渲染使用

* **response类型：渲染数据**

-- 一般在action步骤后面，把action调用之后返回结果，进行渲染

* **end类型：任务结束了**

* **注意：除了end类型步骤，其他类型步骤执行完成之后，推进到下一步**



* **如何推进到下一步？**

-- 无条件跳转，当前步骤执行之后，直接跳转到next下一步

-- 有条件跳转，根据next里面if条件判断，如果条件成立then，条件不成立else

-- 更新active里面step_id



* **action类型步骤分析**

-- 每个流程对应action类，每个action类型实现远程调用

-- 根据yaml文件action属性值，找到对应action对象，远程调用得到结果
