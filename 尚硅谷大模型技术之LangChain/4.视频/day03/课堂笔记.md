##### DEBUG日志

开启日志的debug级别后： 会发现日志的请求参数中一个选项 `idempotency_key` 幂等键

```python
import logging
logging.basicConfig(level=logging.DEBUG)
```

**幂等：**同一个请求重复发送N次，效果和只发1次完全一样，不会产生重负调用所引起的副作用

如何实现幂等调用：设置一个**幂等键**，是一个全局唯一的字符串，例如，在openai的调用中，幂等键大致如下

stainless-python-retry-990d27fd-c1a7-49df-8c35-65d46b07ca66，用来标记一次完整的业务请求

如果请求中携带了同一个幂等键，那么就是重试请求，服务端识别这是重复请求，直接返回上一次已生成好的结果，不重新推理，不计费不重复生成内容

### 3.8 Chains

在langchain中所有Runnable的子类对象，都具有invoke方法，即可以参与链式调用的编排。

##### 三要素

```python
模型调用：`模型客户端对象.invoke`
解析结果：`res = new_client.invoke(input=messages)`
提示词：`提示词模板.invoke`
```

##### 基本方式是：串行链

```python
# 创建可运行序列（创建langchain链）
chains = step1 | step2 | step3
# 通过invoke方法接收输入参数并返回最终结果
最终结果 = chains.invoke(输入参数)
```

##### 并行链：

```python
chains1 = step1 | step2 | step3
chains2 = stepa | stepb | stepc
chains = RunnableParallel(
  key1=chains1,
  key2=chains2
)
最终结果 = chains.invoke(输入参数)
结果1 = 最终结果["key1"]
结果2 = 最终结果["key2"]
```

##### 混合链：

由串行链和并行链灵活组合

## 第4章 RAG

### 4.1 基本概念

#### 什么是RAG

检索增强生成

#### 为什么

1. 模型知识滞后；2.模型有幻觉；3.不想做续训，还想让模型有精准的回答（节省成本）

#### 怎么做

创建RAG知识库索引流程

- 文档加载
- 文档切分：chunks
- 向量转换
- 向量数据库

RAG知识库的搜索流程

- 将问题转换成向量
- 将当前向量和RAG中的chunks向量做相似度比对
- 评选topk文档

并发检索（**向量检索**、假设性问题向量检索、网搜、知识图谱...等等） -> rrf融合重排(基于排名计算得分-算法) ->reranker重排序（基于reranker模型做相关度重排-模型）

两阶段筛选：第一阶段（快：初筛，粗排 - 向量检索，rrf融合重排）、第二阶段（慢：精排 - reranker重排序）

### 4.3 文档切分

#### 为什么要切分

- token的限制：模型上下文窗口有限，无法一次性处理超长文本
- 检索不精确：提交整篇文档，噪声过多，易产生幻觉
- 语义模糊：长文本会稀释关键信息，短文本表达更精确
- 向量化和LLM推理的成本很高：计算和存储成本都很高

#### 切分的核心考量

- 长度控制：不能太大，也不能太小。太大，噪声过多，太小，语义不完整
- 语义完整：不能让句子甚至单词被切断，保持语义的连贯性。否则上下文断裂，影响理解
- 边界合理：不能强行切断，在句子的自然分割处分割。

#### 切分策略

- 按固定字符切：简单，大小均匀。会截断语义。
- 按语义切：语义完整。速度太慢，大小不均匀。

- **按分隔符递归切分：速度快，语义完整，大小均匀**: `RecursiveCharacterTextSplitter`

### 4.4 文档嵌入（文档向量化）

#### 什么是向量化

将自然语言转为向量，依靠向量的相似度实现语义的匹配

#### BERT -> Sentence BERT 进化

原生BERT：可以编码文本，但是不适合直接生成可对比的句子向量

Sentence BERT：改造了BERT的架构和训练任务，生成的语义向量适合进行相似度计算，降低了查找相似句子的计算开销

#### 主流的嵌入模型

开源：BAAI BGE 系列，本地部署非常方便

闭源商用：OpenAI text-embedding 系列，通过API调用

#### 其他考量的维度

向量为辅、最大序列长度（单词能够接收的最长输入文本的长度，一般以token为单位）、是否多语言支持、算力成本

#### 向量转换

单文本、批量文本： HuggingFaceEmbeddings 继承可抽象的 Embeddings

#### 稀疏向量和稠密向量的区别

- 稠密向量：比较语义的相似度
- 稀疏向量：判断关键字的权重



- 稠密向量：大部分都是非零，每个值都有意义。维度越多，语义越丰富
- 稀疏向量：小部分是非零，大部分都是零，只有非零值是有意义的。只统计非零值出现的次数，零值没有意义
