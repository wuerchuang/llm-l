##### DEBUG日志

开启日志的debug级别后： 会发现日志的请求参数中一个选项 `idempotency_key` 幂等键

```python
import logging
logging.basicConfig(level=logging.DEBUG)
```

**幂等：**同一个请求重复发送N次，效果和只发1次完全一样，不会产生重负调用所引起的副作用

如何实现幂等调用：设置一个**幂等键**，是一个全局唯一的字符串，例如，在openai的调用中，幂等键大致如下

stainless-python-retry-990d27fd-c1a7-49df-8c35-65d46b07ca66，用来标记一次完整的业务请求

如果请求中携带了同一个幂等键，那么就是重试请求，服务端识别这是重复请求，直接返回上一次已生成好的结果，不重新推理，不计费不重复生成内容

### 3.8 Chains

在langchain中所有Runnable的子类对象，都具有invoke方法，即可以参与链式调用的编排。

##### 三要素

```python
模型调用：`模型客户端对象.invoke`
解析结果：`res = new_client.invoke(input=messages)`
提示词：`提示词模板.invoke`
```

##### 基本方式是：串行链

```python
# 创建可运行序列（创建langchain链）
chains = step1 | step2 | step3
# 通过invoke方法接收输入参数并返回最终结果
最终结果 = chains.invoke(输入参数)
```

##### 并行链：

```python
chains1 = step1 | step2 | step3
chains2 = stepa | stepb | stepc
chains = RunnableParallel(
  key1=chains1,
  key2=chains2
)
最终结果 = chains.invoke(输入参数)
结果1 = 最终结果["key1"]
结果2 = 最终结果["key2"]
```

##### 混合链：

由串行链和并行链灵活组合

## 第4章 RAG

### 基本概念

#### 什么是RAG

检索增强生成

#### 为什么

1. 模型只是滞后；2.模型有幻觉；3.不想做续训，还想让模型有精准的回答（节省成本）

#### 怎么做

创建RAG知识库索引流程

- 文档加载
- 文档切分：chunks
- 向量转换
- 向量数据库

RAG知识库的搜索流程

- 将问题转换成向量
- 将当前向量和RAG中的chunks做相似度比对
- 评选topk文档

并发检索（**向量检索**、假设性问题向量检索、网搜、知识图谱...等等） -> rrf融合重排(基于排名计算得分-算法) ->reranker重排序（基于reranker模型做相关度重排-模型）

两阶段筛选：第一阶段（快：初筛，粗排 - 向量检索，rrf融合重排）、第二阶段（慢：精排 - reranker重排序）
